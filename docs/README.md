# mlir-sbt 项目文档

mlir-sbt 是一个基于 LLVM/MLIR 的静态二进制翻译实验框架。项目的近期目标是先完成 x86-64 到 x86-64 的翻译闭环，并在此过程中验证一套面向二进制翻译、可以逐步降级到 LLVM IR 的中间表示。

本目录中的文档分为以下几部分：

- [总体设计](architecture.md)：项目边界、翻译流水线、模块职责和建议架构。
- [IR 设计](ir.md)：现有 IR0/IR1、目标语义模型、操作集合与降级策略。
- [阶段目标](roadmap.md)：从当前原型到 x86 → x86 可执行闭环的里程碑和验收标准。
- [开发指南](development.md)：构建、运行、测试方法以及当前实现状态。
- [指令测试流程](testing.md)：fixture 格式、原生 ISA 基准、`sbt` 静态翻译路径与状态比较规则。

## 一句话架构

```text
x86 ELF/目标文件
  → LLVM Object/MC 解码
  → IR0（保真机器指令）
  → CFG 与程序状态恢复
  → IR1（架构语义 + 基础操作）
  → MLIR 标准/LLVM Dialect
  → LLVM IR
  → x86 目标文件/可执行文件
```

## 当前状态

截至 2026-08-13，仓库已经具备 ADD、SUB 指令族的纵向翻译切片：

- 读取 LLVM 支持的目标文件，并依据文件 triple 选择 x86 MC 后端；
- 发现 ELF 函数、逐函数反汇编，并生成带基本块和显式边的 IR0 CFG；
- 使用自定义 TableGen 工具生成 x86 opcode 到转换器的分派代码；
- 将 x86 `ADD`、`SUB` 的已覆盖寄存器、立即数和内存形式转换为 IR1；
- 将当前 IR1 子集完整降级到 LLVM Dialect/LLVM IR，并发射 x86 目标文件；
- 对每个指令 fixture 同时执行宿主原生基准和 `sbt` 静态翻译产物，比较寄存器、
  flags 和内存。

当前闭环仍限于指令级片段；控制流、程序映像、异常、系统接口和通用 guest
内存尚未完成。因此，项目已经能运行受约束的静态翻译单元，但还不是完整的
程序级二进制翻译器。

## 设计原则

1. **语义正确优先。** 每个阶段都应保留源程序可观察行为，包括寄存器、标志位、内存、控制流和异常。
2. **IR 保持小而正交。** 普通计算优先复用 MLIR/LLVM 已有操作，只为二进制翻译特有的状态和语义增加操作。
3. **保真层与规范化层分离。** IR0 保存源指令事实，IR1 表达规范化语义，不让 opcode 枚举直接渗透到优化和后端。
4. **按需计算架构状态。** 标志位等隐式状态要显式建模，并允许数据流分析删除未使用计算。
5. **每一步可验证、可打印。** 反汇编、提升、规范化、降级和代码生成都应有独立检查点。
