# 阶段目标

## 1. 规划方法

项目总目标“完成 x86 → x86 指令翻译”范围很大。建议使用可执行、可差分验证的纵向切片推进：每个里程碑都从机器码输入走到机器码输出，然后逐步扩大指令和程序形态，而不是先实现大量互不连通的指令转换器。

状态标记：

- **已具备**：仓库已有可运行原型；
- **进行中**：已有部分实现，但未达到验收标准；
- **规划**：尚未形成实现。

## 2. 当前基线（已具备）

目标：证明 LLVM MC、MLIR Dialect 和生成式 opcode 分派可组合。

已有结果：

- x86 ELF 代码 section 可被反汇编为 `MCInst`；
- IR0 可以记录并打印地址和汇编；
- IR1 Dialect 和 C++ builder 可生成；
- 当前测试矩阵中的 ADD 寄存器、立即数、内存读写编码可提升为 IR1；
- 当前 IR1 子集可完整降到 LLVM Dialect/LLVM IR，并发射 x86 目标文件；
- 30 个 ADD fixture 已接入原生和静态翻译双路径测试，完整比较寄存器、flags
  和测试内存。

基线已经完成指令级 ADD 纵向闭环，但不等于程序级翻译完成：当前没有从输入
恢复 CFG，state ABI 尚未覆盖 RIP、段基址和异常，guest 内存也仍是受约束的
fixture 槽。测试细节见[指令测试流程](testing.md)。

## 3. M0：稳定原型基础设施

目标：让现有行为可重复、错误可见、测试可自动执行。

工作项：

- 明确支持的输入格式与架构，拒绝非 x86 输入；
- 修复 `getMachine` 对不支持架构没有返回值的问题；
- 为 decode fail、未知 opcode、已分派但未实现的 opcode 返回结构化错误；
- 将 `IR1Context::verify()` 放入提升和每次 lowering 之后，并让失败影响退出码；
- 建立 CTest/lit 测试入口，不再依赖手工执行 shell 脚本；
- 增加 `--dump-*` 与 `--stop-after` 选项；
- 在 CI 中完成 debug build 和单元测试。

验收标准：干净环境可一条命令构建和测试；不支持的输入必定非零退出；测试结果不依赖仓库内预生成二进制。

## 4. M1：ADD 纵向闭环（进行中）

目标：把一组无控制流的 ADD 片段从 x86 对象文件翻译成可执行 x86 代码，并与原片段差分比较。

工作项：

- 定义 64 位规范 GPR 和子寄存器读写；
- 统一操作数宽度、立即数扩展和结果类型；
- 正确实现 CF/PF/AF/ZF/SF/OF；
- 完成 base/index/scale/displacement 有效地址计算；
- 将必要的 IR1 操作完整降到 arith/LLVM Dialect；
- 转换为 `llvm::Module` 并通过 x86 TargetMachine 发射目标文件；
- 建立测试 harness，输入寄存器/flags/内存并比较原始与翻译结果（确定性 fixture
  已完成，随机差分尚未完成）。

首批支持矩阵：

- `ADD r, r`：8/16/32/64 位；
- `ADD r, imm`：覆盖 imm8 符号扩展和全宽立即数形式；
- `ADD r, [mem]` 与 `ADD [mem], r/imm`：先覆盖无 FS/GS、非原子访问；
- AL/AX/EAX/RAX 以及 AH 等高 8 位寄存器别名。

验收标准：所有支持形式均生成不含 IR1 操作的 LLVM IR；至少包含边界值和随机值的差分测试；结果、已定义 flags 和内存效果一致。

## 5. M2：基本块内整数语义

目标：支持无控制流的常用整数基本块。

按语义族扩展：

- 数据移动：MOV、MOVZX、MOVSX、LEA；
- 算术：SUB、INC、DEC、NEG、CMP；
- 逻辑：AND、OR、XOR、TEST、NOT；
- 移位：SHL、SHR、SAR，随后 ROL/ROR；
- 栈操作：PUSH、POP（受约束 ABI）；
- 乘除：MUL/IMUL/DIV/IDIV，最后处理精确异常。

每增加一族都必须同时完成：编码覆盖表、IR 语义、lowering、边界测试和随机差分测试。

验收标准：由上述指令构成的直线基本块可端到端翻译；不读取未建模状态；unsupported coverage 报告清晰可查。

## 6. M3：直接控制流与函数

目标：翻译具有条件分支、循环和直接调用的单模块程序。

工作项：

- 递归下降式代码发现和基本块划分；
- JMP/Jcc 与条件码读取；
- CALL/RET、栈和最小 SysV x86-64 ABI；
- 状态在 CFG 上的 SSA 合并；
- 内部符号与 relocation 处理；
- 源 PC 到生成代码的映射。

验收标准：整数循环、if/else、内部函数调用程序可翻译运行；CFG verifier 通过；与原程序输出和最终状态一致。

## 7. M4：对象文件与外部世界

目标：从孤立片段扩展到受约束的真实 ELF 程序。

工作项：

- 完整 section/symbol/relocation 模型；
- 数据 section 和全局变量；
- 外部函数调用桥接；
- PLT/GOT 的明确处理策略；
- 受支持的系统调用或 libc ABI；
- 生成可链接对象，并提供链接驱动。

验收标准：可翻译并运行一组无动态代码生成、无异常控制流的小型 C 程序。

## 8. M5：间接控制流和运行时

目标：覆盖函数指针、switch jump table 和不能完全静态解析的目标。

工作项：

- jump table 识别；
- 间接目标集合分析；
- guest PC → translated PC 映射；
- dispatcher/runtime ABI；
- 未翻译目标的安全失败或按需翻译策略。

验收标准：间接 call/jump 只会到达验证过的翻译入口；错误目标产生确定性诊断，不跳入生成代码中部。

## 9. M6：语义覆盖与稳健性

目标：逐步接近实用 x86-64 用户态覆盖。

后续主题包括：

- SSE/AVX 与浮点环境；
- atomic、内存顺序和多线程；
- FS/GS、TLS；
- signal、异常和 unwind；
- CPUID/feature 依赖；
- 自修改代码（明确不支持，或引入动态失效机制）；
- 安全强化、模糊测试和性能优化。

这些能力应在整数单线程闭环稳定后按应用需求排序，不宜过早扩大范围。

## 10. 跨阶段质量门槛

每个里程碑统一满足：

1. **语义表**：列出支持的 opcode/operand form、flags、异常和限制。
2. **失败封闭**：未知或不支持语义必须停止翻译或进入明确 fallback。
3. **结构验证**：每个 Pass 后运行 MLIR verifier，最终不得残留 illegal dialect。
4. **差分测试**：比较架构可观察状态，不只比较 IR 文本。
5. **回归测试**：每个修复至少增加一个最小复现。
6. **可诊断性**：错误包含 guest PC、字节和反汇编文本。
7. **性能记录**：从 M3 起记录生成代码大小、翻译时间和运行时间，但正确性优先。
